# 我开源了一个 Codex 工作台，专门处理那些反复交给 AI 的活

如果你经常用 AI 做内容审核、整理文字、生成图文，可能遇到过这样的情况：

一项工作已经试过几次，知道该怎么提要求，也知道想要什么结果。但下一次做同样的事，还是要打开对话、粘贴要求、补充材料，再把结果整理出来。

任务多一点，还要额外记住：哪个做完了，哪个失败了，图片存在哪里，哪些结果已经交给了业务系统。

这些零碎操作，往往占掉了不少时间。

我把围绕这类需求做的一套工具整理成了开源项目，叫 **Codex Agent Platform**。

它是一个可以部署在自己服务器上的 AI 任务工作台：**把一类工作的要求保存下来，以后提交新的材料，让 Agent（执行任务的 AI 助手）自主处理，再按约定交回结果。**

如果你正在尝试把 AI 用进自己的产品，或者团队里已经有一些反复出现的 AI 工作，希望这个项目能给你提供一个起点。

## 它主要解决什么问题？

举一个内容审核的例子。

你有一篇文章，希望 AI 检查其中有没有缺乏依据的表述、明显错误，或者不符合要求的内容。审核完成后，你需要明确的结论和理由，交给编辑或后续系统继续处理。

当这个需求每天都要发生时，你通常会希望：

- 审核要求可以保存，下一篇文章不用重新解释。
- 每次交付的结果都有明确格式，方便继续使用。
- 能看到哪些任务还在处理，哪些已经完成，哪些出了问题。
- 增加另一类工作时，能继续复用现有的管理方式。

Codex Agent Platform 负责把这些事情接起来。你先定义清楚“输入什么、要完成什么、最后交付什么”，再把每次的新材料送进来。

任务的排队、执行记录、结果和文件，都在同一个工作台里管理。需要对接现有产品时，也可以由你的系统提交任务、接收结果。

## 把完整目标交给 Agent，让它自己安排工作

做这个项目时，我很在意的一点，是尽量让 Agent 自己理解并完成任务。

比如一项图文创作工作，你可以一次交代主题、篇幅、画面风格和交付要求。Agent 根据这些要求安排构思、写作、配图和检查，最后提交结果。

**你一次说明完整目标和交付要求，Agent 自己安排步骤，完成后统一交付结果。**

每次提交对应一个独立任务，有自己的执行过程和结果记录。原来保存的要求可以复用，新任务又有各自的上下文，方便区分和追踪。

在项目里，这种保存下来的业务配置叫“业务插件”。理解起来，就是一种可以反复使用的任务模板。

它可以约定审核文章，也可以约定整理摘要、写图文故事。现有工具能够覆盖需求时，新增一类任务不必修改平台源码；如果缺少新的底层能力，再补上对应工具。

## 可以拿它做哪些事？

项目目前自带了内容审核和图文小说两个示例。下面这些场景，可以帮助你理解它的用法。

**内容审核：把标准固定下来，把结论交回来。**

业务系统提交正文和审核关注点，Agent 根据要求处理，返回是否通过以及判断依据。编辑可以继续阅读这些结果，系统也可以把它们接到后续流程里。

这里，审核“不通过”同样是一种明确的业务结果。任务有没有顺利执行，和内容是否符合标准，可以分别查看。

**图文创作：围绕一个主题，交付正文和配图。**

你提供故事梗概、题材、章节要求和画面风格，Agent 自主完成创作与自查，保存正文和生成的图片。完成后，可以从任务记录里查看结果、取出文件。

图片生成是否可用，取决于你自己的账户权限和任务配置；具体内容仍然需要按实际用途评估质量。

**定期执行：让固定工作按时间进入队列。**

有些工作适合每天或每周做一次。你可以为已配置的业务设置定时计划，也可以安排管理 Agent 检查平台的任务积压、执行错误和交付情况，给出调查报告。

这些例子只是起点。你已经验证可行的 AI 工作，只要能用现有能力表达清楚输入、要求和输出，就值得试着整理成自己的任务模板。

## 工作台里，还有一个可以对话的管理 Agent

任务开始多起来以后，另一个很实际的问题是：怎么管？

所以，项目除了有查看状态和配置的页面，也提供了一个管理 Agent。它可以通过平台开放的管理工具，查询记录、调查问题、调整配置。

你可以直接提出这样的要求：

> 看看最近失败的任务，先查具体记录，再告诉我原因。

> 暂停领取新任务，让已经开始的工作继续处理。

> 给我增加一个文本摘要任务，输入一段文字，输出简短摘要和要点。先保存，暂时不要执行。

> 把这个已失败的任务重新提交一次，保留原来的记录。

管理 Agent 可以帮助你完成这些操作，你也可以在页面里查看和调整。普通配置修改可以直接保存生效，减少日常维护时反复改文件、重启服务的操作。

我希望它能让“使用 AI 工作”与“管理这些工作”连在一起：既可以把任务交出去，也能方便地知道它们进行得怎么样。

## 哪些人可能会需要它？

我觉得它尤其适合三类人：

- **独立开发者和产品开发者。** 已经找到一个可行的 AI 用法，希望把它接进自己的网站、应用或内部工具。
- **有重复工作的小团队。** 内容审核、文字整理、图文制作等任务有相对固定的要求，希望减少每次组织材料、重复交代和整理结果的操作。
- **已经在使用 Codex 的人。** 希望在现有使用方式之外，增加可复用的任务、定时安排和统一记录。

当前版本更适合个人运营者，或者共享管理权限、彼此信任的小团队。如果要直接面向大量独立客户提供商业服务，还需要进一步建设相应的账户、权限和运营能力。

## 为什么把它开源？

不同人的业务很不一样，但接入 AI 工作时，常常都会遇到相似的问题：要求怎样复用，任务怎样提交，结果怎样交回来，出了问题怎样查看。

我希望把这一部分通用能力开放出来，让有类似需求的人能少做一些重复建设。

你可以在自己的部署里管理任务配置和记录，也可以按照项目提供的方式修改系统提示词、增加业务模板。项目采用 MIT 许可证开源，欢迎试用、反馈问题，也欢迎参与改进。

目前它仍处于预览阶段，需要自行部署，并使用具备 Codex 权限的 ChatGPT 账户。模型执行依赖 OpenAI 服务，开源和自托管并不意味着模型调用免费或完全离线。

如果你想试，建议先拿一件已经明确的小工作跑通：一篇文章的审核，一段文字的摘要，或者一个短篇图文故事。确认结果适合自己的需求，再考虑接入实际业务。
