# Chat progress, image input and local feedback implementation plan

**Goal:** Make management chat execution visible with ordered queued messages, collapsed per-message activity, compressed images, copy controls and independent loading feedback.

**Design:** Preserve the existing durable per-conversation FIFO. Persist bounded public reasoning summaries, assistant text and tool lifecycle metadata against the originating user message, never raw reasoning, tool arguments/results or image data in progress records. Render queued/running/recovering/terminal states and partial replies; keep activity collapsed until expanded. Poll the active chat without blanking existing content or presenting background polls as user actions. Switching conversations shows an independent initial loader and ignores late responses. Multiple submitted messages queue rather than run concurrent turns in the same thread.

Images are selected, pasted or dropped with previews/removal. Frontend rasterizes JPEG/PNG/WebP to a max 2048px edge and at most 160 KiB each, at most four images per message. Reject sources above 20 MiB or 40 million pixels. Messages accept image-only input; text is limited to 20,000 characters, keeping the JSON envelope below the existing 1 MiB server/Nginx limit. Backend validates actual image bytes, dimensions and count independently, persists private image data and exposes authenticated preview routes. Images enter the same single initial Codex turn as text, using the pinned protocol's image input. Refresh/recovery preserves queued images and does not replay completed work.

Copy assistant bubble source Markdown and fenced code separately, with local copying/success/failure feedback. Every asynchronous user action gets local busy feedback and duplicate protection; unrelated actions stay usable. Keep React/TypeScript/Ant Design, safe Markdown, localization and existing credential boundaries.

**Interfaces:** POST messages `{text:string,attachments?:{name:string,dataUrl:string}[]}`. `Message` adds `reply_to?:string|null`, `started_at/completed_at/updated_at?:number|null`, `attachments?:{id,name,mime,width,height,size,url}[]`, `activity?:{id,kind:'reasoning_summary'|'assistant_message'|'tool'|'status',label:string,text:string,status:string,created_at:number,updated_at:number}[]`. Preview `url` is an authenticated same-origin `/admin/api/conversations/{conversationId}/images/{attachmentId}` route, never a local path. Actions add `message_id?:string|null`. Conversation list optionally includes `queued_count/running_count`. Context adds `chatImages:{id,name,dataUrl,size,width,height}[]` and its React setter, cleared on logout and preserved across navigation. No raw data URLs in conversation JSON, logs or activity. Tool names/status only; sanitized public summaries and assistant text are bounded.

**Review focus:** Events from another thread/turn or after finalization; token leakage across fragmented deltas; corrupted or oversized raster inputs; queued image-only messages across restart; switching chats/pages or logout while send/compression/save requests are pending.
