# Per-plugin integration documentation implementation plan

**Goal:** Give each business plugin a readable, current integration contract and copyable examples from its own Admin list action.

**Architecture:** Add a human-authenticated read-only Manager endpoint `/admin/api/plugins/:type/integration?locale=zh-CN|en`. It reads the current plugin definition and safe human connection metadata, then deterministically derives Markdown sections from actual HTTP/task/callback behavior and the input/result JSON Schemas. No model turn, real task submission, new Agent permission or credential retrieval. A React/Ant Design drawer shows section tabs, independent loading/retry, code copy and full Markdown copy/download. Existing complex plugin editing remains in management chat.

**Design choices:** Generate from saved contract plus fixed transport rules rather than a free-form Agent-authored document that can drift. Schema annotations remain the source of business field meaning; missing descriptions are shown honestly and complex/recursive schemas retain their complete source. Example values must validate or be clearly unavailable, never silently fabricate valid-looking requests. Relative entry paths use an explicit gateway-host placeholder, never the Admin origin. Secret values and actual callback URLs/query parameters are omitted from exports. Document async HTTP202 admission separately from completion, no request_id deduplication, plugin-scoped Bearer auth, query/artifact APIs and callback2xx/unknown semantics.

Preserve the original Manager-only dependency boundary.
- [x] Frontend RED/GREEN: row action, accessible responsive tabs, independent loading/retry/stale selection guards, code/full copy and Markdown download, missing-setup guidance and locale behavior. Inspect final desktop/phone captures and fix narrow schema cells with a scoped rule.
