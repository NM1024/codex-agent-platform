# 管理 Agent 本地代码沙箱设计（基础可用）

日期：2026-10-30（Asia/Shanghai）

状态：设计稿，未实施。范围为现有平台内部的一组本地隔离工具。

## 1. 要达到的效果

管理 Agent 有需要时，可以在自己的临时空间中写 Python / JavaScript、处理数据、生成文件和运行普通测试，执行后读取真实结果，并把需要交付的文件放到管理对话中供用户下载。

每个管理对话独立，不接触其他对话、平台数据库、登录信息或宿主文件。普通管理对话和定时管理巡检共用同一套工具与限制，不增加巡检专用配置体系。

## 2. 只保留这些功能

| 功能 | 行为 |
| --- | --- |
| 文件操作 | 列目录、读文本、创建、修改和删除当前沙箱内文件 |
| 命令执行 | 执行 Python、Node.js 和容器内普通命令，返回 stdout、stderr、退出码 |
| 执行控制 | 查询当前执行、读取有界输出、取消；每个对话同时只运行一条命令 |
| 文件交付 | 将沙箱内文件保存为当前对话附件，文本/常见图片可预览，其他文件可下载 |
| 自动创建与回收 | 第一次需要时创建；闲置、超时、异常或删除对话时按下述规则销毁 |

不建设远程节点、调度集群、独立作业数据库、快照、环境版本管理、包源代理、通用联网网关、文件 IDE、独立运维后台或长期后台服务。

## 3. 简单的实现方式

使用本机 Docker 和一个平台固定的 Python + Node.js 沙箱镜像。一个对话在使用期间对应一个临时容器，所有可写文件位于该容器自己的临时空间，不挂载宿主工作目录。

Manager 通过现有管理 MCP 暴露沙箱工具，增加一个很薄的本机容器适配模块，负责创建、执行和销毁。沿用现有部署侧受控本机入口的安装方式；这不是远程执行服务，不需要新的队列或数据库。

现有 Manager 本身运行在容器里，又不能挂载 Docker socket，因此创建容器需要一个部署侧受信本机入口。该入口只接受固定的沙箱操作：固定镜像、固定挂载形式、资源限制和本系统沙箱标识。它是新增的受控适配入口，不把现有升级接口扩成任意命令接口，也不允许模型传递任意 Docker 参数。命令只作为容器内执行参数传递，不在宿主 Shell 中拼接解释。Docker 控制权限留在受信宿主入口，Manager 和沙箱都不挂 Docker socket。

沙箱镜像不包含 Codex、平台代码、登录文件或平台令牌。当前 Codex 原生 Shell 继续关闭，代码执行通过专用沙箱工具完成。

## 4. 最小必要隔离

- 非 root 用户、只读根文件系统、独立容器进程与网络空间、去除额外 capabilities、禁止提权。
- 不注入宿主环境、管理 MCP token、RUNNER_TOKEN、Codex 登录、SSH、云凭证或更新器通道。
- 文件工具的路径只能相对当前沙箱；拒绝目录穿越、越界链接和特殊文件，不接受宿主绝对路径。
- 对话身份由 MCP 服务端确定。模型不能指定其他对话、容器 ID、宿主挂载或控制参数。
- 文件登记与修改只在命令停止后进行，避免边执行边读取变化中的交付文件。
- 执行普通 Docker 容器，不强制引入 gVisor、微虚拟机或独立执行主机；不宣称普通容器具有独立内核。

建议的固定默认限制：

| 项目 | 初始设定 |
| --- | --- |
| CPU | 每个沙箱最多 1 vCPU |
| 内存 | 每个沙箱最多 1 GiB，限制 swap |
| 进程数 | 最多 128 |
| 文件空间 | `/workspace` 使用 256 MiB tmpfs，并限制 inode；`/tmp` 使用 64 MiB tmpfs |
| 单条命令 | 默认 60 秒，最多 120 秒 |
| 保留输出 | stdout/stderr 各最多 64 KiB，超出截断并继续排空管道 |
| 单次交付文件 | 最多 20 MiB |
| 容器数 | 默认最多 2 个，防止多对话占满机器 |

工作文件和临时目录计入内存上限。使用有界 tmpfs，避免为了临时磁盘再引入存储配额系统；镜像和宿主容器日志另作固定上限，不能形成无限日志写入。

这些是待验证的起始值，部署时可以配置，Agent 不能自行调高。基础限额或网络隔离无法生效时关闭沙箱执行，其他管理功能继续正常工作。

## 5. 创建、执行和销毁规则

1. 首次写文件或执行命令时按需创建。仅查看聊天或查询状态不创建容器。
2. 同一对话连续使用时复用容器和文件；一条命令结束后才接受下一条命令，不做任务排队。
3. 命令完成后确认没有遗留子进程；若无法清干净，销毁整个容器。禁止通过后台进程绕开执行时间。
4. 超时、用户取消、内存超限或异常失控时，终止并销毁整个沙箱，确保子进程一并结束；临时文件可能丢失，工具明确返回需要重建。
5. 闲置 30 分钟自动销毁。容量不足时可回收最久未使用的空闲沙箱；仍有活动命令时不抢占，返回 busy。被回收的对话在下次调用时明确看到临时空间已清空。
6. 删除对话时销毁其沙箱。Manager 或本机启动器重启后清理属于本系统的旧沙箱，不自动恢复或重跑命令；只能清理明确归属本安装的容器，不能影响其他 Docker 容器。

本机入口承担简单的闲置检查、执行超时与取消；Manager 不在线也不能使沙箱无限执行。启动器重启先清理旧沙箱再接收调用，沿用本机服务的自动重启方式，不增加节点租约和分布式恢复协议。

执行记录只保留必要的 ID、状态和有界结果，可关联现有管理动作记录。受理后的命令通过执行 ID 查询，不因工具调用超时自动重新执行；取消未获确认时如实显示仍在取消，不能假报已停止。HTTP 返回丢失时核对原执行记录，结果无法确认就说明未知。

工作文件是临时数据，不承诺跨系统重启保留。需要保留的成果先登记为对话附件；附件不随容器回收而丢失。

## 6. 普通代码和依赖

固定镜像提供 Python、Node.js，以及一组常用的测试、数据分析和绘图库，例如 pytest、numpy、pandas、matplotlib、Pillow；Node.js 提供内置测试和标准库。镜像依赖固定版本，具体清单在构建验证时确定，工具可查询实际可用库。

沙箱默认始终断网，本版不开放 Agent 自行联网安装依赖。镜像可以保留 pip/npm，但它们不能绕过断网限制。缺少依赖时明确返回缺包原因，由部署者调整镜像预装清单；不增加在线依赖管理系统、安装专用容器或临时网络授权流程。

本次明确后置在线安装，而不是把“安装命令存在”当作已经支持联网安装。若实际任务证明需要，再单独增加少量受控包源支持。

## 7. 给 Agent 的四个工具

| 工具 | 内容 |
| --- | --- |
| `sandbox_files` | 状态/目录/读写/修改/删除；返回沙箱是否存在、文件信息和有界内容 |
| `sandbox_exec` | 在当前对话沙箱内执行命令；返回执行 ID，可短暂等待结果 |
| `sandbox_process` | 查询状态与 stdout/stderr/退出码，或取消当前执行 |
| `sandbox_publish` | 将选定普通文件保存为当前对话附件 |

工具参数不暴露宿主路径、容器配置或其他对话身份。执行 ID 和文件归属再次校验。文件大于工具回包上限时分段读取，不把完整大文件塞给模型。

沙箱内容、程序输出和依赖说明只是数据，不能授权新的平台管理操作。平台配置、服务重启、插件管理等仍使用原有 MCP。同步调整 AGENTS.md、工具策略和管理提示词，准确允许“沙箱内编程和测试”，保留平台源码/宿主 Shell 的现有限制。

## 8. 结果交付和管理页面

沿用现有聊天与附件的交互，不增加独立工作台：

- 执行中展示一张简洁状态卡，支持取消；结束后可查看退出码和折叠输出。
- Agent 发布的文件显示在对应回复附近，可以预览或下载。
- 文本按纯文本显示，常见图片进行大小/像素检查；HTML、SVG、PDF、ZIP 等默认附件下载，不在管理页面执行或增加文档转换服务。
- 发布时复制成平台保存的稳定附件，校验归属、普通文件类型、大小和路径；拒绝链接与特殊文件，不直接把容器目录映射为网页目录。
- 下载沿用 Admin 登录和对话归属校验；文件放在管理对话产物区，不复用业务任务身份。
- 临时文件随沙箱销毁；正式附件跟随现有对话保留/删除策略，不另设一套历史管理系统。

## 9. 基础验收

实际验证：Python/Node 执行、修改后重跑、运行普通测试、生成图片/报告并下载；两个对话互不可读；读不到平台文件/凭证；默认无法联网；CPU/内存/PID/tmpfs/输出有界；超时/取消/遗留子进程能回收；重启不重跑；已发布附件在沙箱销毁后仍可下载。

本次交付只需上述工具与安全边界形成闭环，不扩展远程、快照、调度、复杂环境或运维体系。业务实现尚未开始。
