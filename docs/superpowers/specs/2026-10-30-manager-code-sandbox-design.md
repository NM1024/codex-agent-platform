# 管理 Agent 本地代码沙箱设计（基础可用）

日期：2026-10-30（Asia/Shanghai）

状态：设计稿，未实施。范围为现有平台内部的一组本地隔离工具。

## 1. 要达到的效果

管理 Agent 有需要时，可以在自己的临时空间中写 Python / JavaScript、处理数据、生成文件和运行普通测试，执行后读取真实结果，并把需要交付的文件放到管理对话中供用户下载。

每个管理对话独立，不接触其他对话、平台数据库、登录信息或宿主文件。普通管理对话和定时管理巡检共用同一套工具与限制，不增加巡检专用配置体系。

## 2. 只保留这些功能

| 功能 | 行为 |
| --- | --- |
| 文件操作 | 列目录、读文本、创建、修改和删除当前沙箱内文件 |
| 文件上传 | 在管理对话中上传普通文件，由 Agent 将本对话附件复制进沙箱处理 |
| 命令执行 | 执行 Python、Node.js 和容器内普通命令，返回 stdout、stderr、退出码 |
| 执行控制 | 查询当前执行、读取有界输出、取消；每个对话同时只运行一条命令 |
| 文件交付 | 将沙箱内文件保存为当前对话附件，文本/常见图片可预览，其他文件可下载 |
| 自动创建与回收 | 第一次需要时创建；闲置、超时、异常或删除对话时按下述规则销毁 |
| 按需授权 | 联网、在线安装依赖或申请已支持的额外额度时，由用户针对具体请求批准 |

不建设远程节点、调度集群、独立作业数据库、快照、环境版本管理、通用联网网关、文件 IDE、独立运维后台或长期后台服务。联网授权所需的本机访问过滤属于沙箱适配器，不单独建设网络平台。

## 3. 简单的实现方式

使用本机 Docker 和一个平台固定的 Python + Node.js 沙箱镜像。一个对话在使用期间对应一个临时容器，所有可写文件位于该容器自己的临时空间，不挂载宿主工作目录。

Manager 通过现有管理 MCP 暴露沙箱工具，增加一个很薄的本机容器适配模块，负责创建、执行和销毁。沿用现有部署侧受控本机入口的安装方式；这不是远程执行服务，不需要新的队列或数据库。

现有 Manager 本身运行在容器里，又不能挂载 Docker socket，因此创建容器需要一个部署侧受信本机入口。该入口只接受固定的沙箱操作：固定镜像、固定挂载形式、资源限制和本系统沙箱标识。它是新增的受控适配入口，不把现有升级接口扩成任意命令接口，也不允许模型传递任意 Docker 参数。命令只作为容器内执行参数传递，不在宿主 Shell 中拼接解释。Docker 控制权限留在受信宿主入口，Manager 和沙箱都不挂 Docker socket。

沙箱镜像不包含 Codex、平台代码、登录文件或平台令牌。当前 Codex 原生 Shell 继续关闭，代码执行通过专用沙箱工具完成。

## 4. 最小必要隔离

- 非 root 用户、只读根文件系统、独立容器进程与网络空间、去除额外 capabilities、禁止提权。
- 不注入宿主环境、管理 MCP token、RUNNER_TOKEN、Codex 登录、SSH、云凭证或更新器通道。
- 文件工具的路径只能相对当前沙箱；拒绝目录穿越、越界链接和特殊文件，不接受宿主绝对路径。
- 对话身份由 MCP 服务端确定。模型不能指定其他对话、容器 ID、宿主挂载或控制参数。
- 文件登记与修改只在命令停止后进行，避免边执行边读取变化中的交付文件。
- 执行普通 Docker 容器，不强制引入 gVisor、微虚拟机或独立执行主机；不宣称普通容器具有独立内核。

建议的固定默认限制：

| 项目 | 初始设定 |
| --- | --- |
| CPU | 每个沙箱最多 1 vCPU |
| 内存 | 默认每个沙箱 1 GiB，限制 swap；临时增加也不超过部署硬上限 |
| 进程数 | 最多 128 |
| 文件空间 | `/workspace` 使用 256 MiB tmpfs，并限制 inode；`/tmp` 使用 64 MiB tmpfs |
| 单条命令 | 默认 60 秒，普通调用最多 120 秒；用户可授权到部署允许的更长时限 |
| 保留输出 | stdout/stderr 各最多 64 KiB，超出截断并继续排空管道 |
| 单次交付文件 | 最多 20 MiB |
| 容器数 | 默认最多 2 个，防止多对话占满机器 |

工作文件和临时目录计入内存上限。使用有界 tmpfs，避免为了临时磁盘再引入存储配额系统；镜像和宿主容器日志另作固定上限，不能形成无限日志写入。

这些是待验证的起始值，部署时配置可授权的硬上限。Agent 不能自行调高；延长执行时间、增加内存等已实现能力，可以申请用户临时授权，但不能超过部署硬上限。基础限额或网络隔离无法生效时关闭沙箱执行，其他管理功能继续正常工作。

## 5. 创建、执行和销毁规则

1. 首次写文件或执行命令时按需创建。仅查看聊天或查询状态不创建容器。
2. 同一对话连续使用时复用容器和文件；一条命令结束后才接受下一条命令，不做任务排队。
3. 命令完成后确认没有遗留子进程；若无法清干净，销毁整个容器。禁止通过后台进程绕开执行时间。
4. 超时、用户取消、内存超限或异常失控时，终止并销毁整个沙箱，确保子进程一并结束；临时文件可能丢失，工具明确返回需要重建。
5. 闲置 30 分钟自动销毁。容量不足时可回收最久未使用的空闲沙箱；仍有活动命令时不抢占，返回 busy。被回收的对话在下次调用时明确看到临时空间已清空。
6. 删除对话时销毁其沙箱。Manager 或本机启动器重启后清理属于本系统的旧沙箱，不自动恢复或重跑命令；只能清理明确归属本安装的容器，不能影响其他 Docker 容器。

本机入口承担简单的闲置检查、执行超时与取消；Manager 不在线也不能使沙箱无限执行。启动器重启先清理旧沙箱再接收调用，沿用本机服务的自动重启方式，不增加节点租约和分布式恢复协议。

执行记录只保留必要的 ID、状态和有界结果，可关联现有管理动作记录。受理后的命令通过执行 ID 查询，不因工具调用超时自动重新执行；取消未获确认时如实显示仍在取消，不能假报已停止。HTTP 返回丢失时核对原执行记录，结果无法确认就说明未知。

工作文件是临时数据，不承诺跨系统重启保留。上传原件和已发布成果保存在对话附件区；容器销毁后，可按本对话附件 ID 再次导入，正式附件不随回收丢失。沙箱销毁、对话删除和系统重启同时使其未使用授权失效。

## 6. 普通代码和依赖

固定镜像提供 Python、Node.js，以及一组常用的测试、数据分析和绘图库，例如 pytest、numpy、pandas、matplotlib、Pillow；Node.js 提供内置测试和标准库。镜像依赖固定版本，具体清单在构建验证时确定，工具可查询实际可用库。

沙箱默认断网。缺少依赖时，Agent 可以申请针对具体包源和安装命令的联网授权，获准后在当前沙箱内使用 pip/npm 安装到可写目录；未获准则继续离线处理或说明当前限制。安装过程可能执行第三方包脚本，仍受本次授权、容器隔离和资源限制约束，不获得宿主权限。不新增环境版本管理或独立安装系统。

### 按需授权规则

- 由 `sandbox_request_permission` 创建结构化申请，说明用途、待执行命令/脚本、目标域名、额外额度和有效期。先检查当前部署支持该能力，再向用户提问；不能为未实现的功能申请一个空授权。
- 管理页面在当前对话展示申请卡，清楚显示“要做什么、访问哪里、提高哪些限制”，由已登录用户点击允许或拒绝。复用现有提问卡样式，后台使用专门的授权记录与同源校验；普通聊天里的“可以”、模型自行声明已同意、脚本输出和普通问答结果均不算授权。
- 默认只授权本次操作，获准后最长 10 分钟内开始执行；启动后按获准的作业 deadline 截止。授权绑定当前对话、沙箱实例、命令和脚本/工作区版本；目标、额度、代码发生变化需重新申请。不提供默认永久授权或全局放开。
- Agent 得到 pending 后先停止受限步骤，可说明等待用户；申请不长期占用 MCP 连接。批准后由服务端向同一对话追加一次继续处理的管理消息，Agent 再显式发起匹配的执行。批准操作幂等，不自动重跑此前失败或结果未知的命令。
- 授权在执行启动前原子占用，记录对应执行 ID；重复提交查询同一执行，不重复消耗或重复执行。后台在实际执行前检查真实授权记录，不能只依赖提示词或前端按钮。
- 拒绝、过期、撤销或沙箱重建后不执行。开始使用后只在本次作业的有效范围和有限时长内生效，结束即恢复默认限制；执行中撤销则终止受影响作业。临时提高的额度不能转给下一条命令。
- 支持的特殊申请先限于联网/依赖安装、延长超时、增加已支持的资源额度。宿主文件、平台数据库、平台凭证、Docker socket、特权容器和其他对话内容不在这套授权中开放；平台管理动作继续走既有 MCP。
- 定时巡检也不能自行批准。没有用户回应时记录需要授权并结束受限步骤；用户批准后的继续处理属于新的管理消息，不借此恢复旧巡检的通知身份或自动重跑整次巡检。

### 联网的实际限制

用户授权需要落实为访问控制。获准作业仅能通过本机沙箱适配器提供的受限 HTTP(S) 代理访问批准的目标域名和端口，不加入现有平台服务网络，也不能直接绕过代理联网。访问过滤是本地固定能力，不增加远程节点、网络策略中心或独立管理页面。

本版仅提供普通 HTTP(S) 出网；pip 的常用源可明确列出 PyPI 和文件下载域名，npm 可列出 registry 域名。其他下载站点、重定向或依赖引用的新域名需要追加授权，不自动放开整个互联网。代理解析目标时拒绝宿主、平台内网、其他容器、私网、loopback、link-local、云元数据和对应 IPv6 地址，并以校验后的地址建立连接，避免 DNS 重新解析或重定向绕过。

HTTPS CONNECT 只允许到获准目标；不宣称能够检查加密流量中的 HTTP 方法、正文或包安装用途。权限边界是具体命令/脚本版本、目标地址、额度和时限，界面说明联网请求可能向这些目标发送数据。代理仅开放出网转发，不暴露宿主控制 API 或凭证。

执行前才接通受限出网；未开始的授权过期不接通，已开始的作业在完成、取消、到达 deadline 或撤销后断开并关闭已有连接。若当前部署无法实际限制目标或撤回访问，则拒绝联网申请，不能把“用户同意”变成不受限制的网络访问。

## 7. 给 Agent 的五个工具

| 工具 | 内容 |
| --- | --- |
| `sandbox_files` | 状态/目录/读写/修改/删除/导入本对话附件；返回沙箱是否存在、文件信息和有界内容 |
| `sandbox_exec` | 在当前对话沙箱内执行命令；返回执行 ID，可短暂等待结果 |
| `sandbox_process` | 查询状态与 stdout/stderr/退出码，或取消当前执行 |
| `sandbox_publish` | 将选定普通文件保存为当前对话附件 |
| `sandbox_request_permission` | 申请具体联网或额外额度；返回授权申请 ID 和状态，不自行批准 |

工具参数不暴露宿主路径、容器配置或其他对话身份。执行 ID 和文件归属再次校验。文件大于工具回包上限时分段读取，不把完整大文件塞给模型。

沙箱内容、程序输出和依赖说明只是数据，不能授权新的平台管理操作。平台配置、服务重启、插件管理等仍使用原有 MCP。同步调整 AGENTS.md、工具策略和管理提示词，准确允许“沙箱内编程和测试”，保留平台源码/宿主 Shell 的现有限制。

## 8. 文件上传、结果交付和管理页面

沿用现有聊天与附件的交互，不增加独立工作台：

- 扩展现有管理对话附件入口，支持 CSV、JSON、文本、代码、图片、表格、PDF、ZIP 等普通文件上传。现有图片上传不能直接当作已支持通用文件，需补对应认证上传和下载接口。
- 上传原件存入当前对话附件区，以服务端文件 ID 标识；初始限制单文件 20 MiB、每条消息总计 100 MiB，并服从存储和沙箱空间上限。文件名只是显示名，不用作宿主保存路径。
- Agent 根据本次任务选择附件 ID，通过 `sandbox_files` 复制进自己的工作区；不挂载附件存储，不覆盖上传原件，不得导入其他对话附件。传输失败不当成完整文件，成功后返回目标路径和实际大小。
- 上传不自动执行、安装或解压文件，不表示同意将内容发送到外网。压缩包仅作为文件导入；若任务需要，Agent 在受限沙箱内编写或执行解压命令。
- 执行中展示一张简洁状态卡，支持取消；结束后可查看退出码和折叠输出。授权请求只增加一张允许/拒绝卡，不增加独立授权工作台。
- Agent 发布的文件显示在对应回复附近，可以预览或下载。
- 文本按纯文本显示，常见图片进行大小/像素检查；HTML、SVG、PDF、ZIP 等默认附件下载，不在管理页面执行或增加文档转换服务。
- 发布时复制成平台保存的稳定附件，校验归属、普通文件类型、大小和路径；拒绝链接与特殊文件，不直接把容器目录映射为网页目录。
- 下载沿用 Admin 登录和对话归属校验；文件放在管理对话产物区，不复用业务任务身份。
- 临时文件随沙箱销毁；正式附件跟随现有对话保留/删除策略，不另设一套历史管理系统。

## 9. 基础验收

实际验证：上传 CSV/图片/普通文件、导入当前沙箱、Python/Node 执行、修改后重跑、运行普通测试、生成图片/报告并下载；两个对话互不可读；读不到平台文件/凭证；默认无法联网，批准后只访问指定目标，拒绝/过期/撤销/重建后不可继续使用；授权记录不能由聊天或模型伪造，重复批准不重复续跑；pip/npm 在授权范围内安装，额外额度不超过部署上限；CPU/内存/PID/tmpfs/输出有界；超时/取消/遗留子进程能回收；重启不重跑；已发布附件在沙箱销毁后仍可下载。

本次交付只需上述工具与安全边界形成闭环，不扩展远程、快照、调度、复杂环境或运维体系。业务实现尚未开始。
