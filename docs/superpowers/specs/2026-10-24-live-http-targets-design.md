# Live HTTP target configuration

The user requested configuration through both the management Agent and Admin, replacing the deployment-only workflow. Reuse the existing module-owned configuration system with a new `http_targets` scope, and a dedicated React/TypeScript/Ant Design tab with a target list and a small editor. Generic JSON editing remains unnecessary. Target names map to one URL, an optional Bearer token and a timeout; saving does not send a request. The next HTTP tool call uses the saved target without restarting services. Plugin entry credentials and final callbacks remain separate.

Use `PLATFORM_HTTP_TARGETS_JSON` only to initialize this new scope. Preserve persisted values thereafter and do not revive the retired `configuration:http` record. Scope reads expose URLs and configured-token flags, never token values. Omitted tokens retain existing values; an explicit empty string clears one. Require the scope revision on writes to prevent a stale page or Agent update overwriting another edit. Existing HTTPS/loopback-HTTP validation remains authoritative. The Manager receives current configuration instructions each turn and can manage targets through preset configuration operations; no shell/source access is added, and credentials should be entered on the page rather than in chat.

Alternatives considered: reactivating the retired `http` scope would silently revive obsolete destinations; a second custom storage/API would duplicate existing ownership, secret masking and validation. The new scope reuses those mechanisms while separating old data.
